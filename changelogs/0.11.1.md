# 0.11.1 — token 用量恢复记账，`pydantic-ai-slim` 升到 2.54

发布于 2026-10-08 · 提交范围见 `pyproject.toml` 的 `version` 变动 · [返回索引](CHANGELOG.md)

`genai-prices` 0.1.x 的用量字段与 `pydantic-ai` 2.13 不兼容，token 统计会静默归零；这一版升到上游修好的组合：`pydantic-ai-slim` 2.54.0 + `genai-prices` 0.1.9。同一版里还修掉一处启动崩溃，并把三份锁文件按同一套约束重解、互相对齐。

- **🐛 修复** `genai-prices` 0.1.x 的 `Usage` 会多带出 `pydantic-ai` 2.13 不认的键（如 `output_reasoning_tokens`），让用量提取静默失败、每次模型调用都记成 0——网页控制台日历、预算账本与 TPS 同步归零。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **⬆️ 依赖** `pydantic-ai-slim` 从 `>=2.13.0` 提到 `>=2.54.0`：它是第一个把 `output_reasoning_tokens` 收进 `RequestUsage` 的版本（2.53.0 及以前都没有）；锁文件随之把 `openai` 升到 3.26、`httpx2` 升到 2.13.1，`pydantic` 保持 2.12.5。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **🎨 调整** 模型工厂按 SDK 的 HTTP 库分池：`openai` 3.x 与 `anthropic` 1.x 的 `http_client` 形参只收 `httpx2.AsyncClient`，这两家改传 `httpx2` 池并保留同款 §23 墙钟（connect 15s / read 180s / write 60s / pool 30s），`gemini` 仍走 `httpx` 池；`httpx2>=2.12.0` 同时列为直接依赖。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **⬆️ 依赖** `genai-prices` 的 `<0.1` 上限移除，改为 `>=0.1.9`。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **⬆️ 依赖** `pydantic-ai-skills` 约束到 `<1`：2.x 搭配 harness ≥0.52 会构造只支持 POSIX 的工作区后端，Windows 上构造技能能力即抛 `NotImplementedError`（实测 2.1.0 + harness 0.54.0），等上游支持非 POSIX 再迁。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **⬆️ 依赖** `pytakumi` 最低版本提到 `0.1.5`。[`a0672904`](https://github.com/Genshin-bots/gsuid_core/commit/a0672904)
- **🐛 修复** `gs_logger` 不再从 `starlette.websockets` 取 `WebSocketDisconnected`（该名字只有 starlette 1.7.0 才有）：发送日志时的断连判定改成「连接已掉出 `CONNECTED`」，新旧 starlette 走同一条分支。starlette 0.46.0 与 1.6.0 下各跑一遍全量测试（1944 项）均通过。
- **⬆️ 依赖** `starlette>=0.46.0` 提为直接依赖：`gs_logger` 直接 import `starlette.websockets`，且 0.46.0 起上游 `GZipMiddleware` 才跳过 `text/event-stream`（issue #283）。
- **⬆️ 依赖** `fastapi` 下限 `0.97.0` 提到 `0.115.10`：这是首个允许 `starlette>=0.46` 的版本，更早的 fastapi 把 starlette 上限锁在 `<0.39.0`，与上面的下限互相装不上。
- **⬆️ 依赖** `fastmcp` 下限 `3.0.0` 提到 `3.2.0`：`ToolResult` 所在的 `fastmcp.tools.base` 自 3.2.0 才有（3.1 及以前叫 `fastmcp.tools.tool`），按旧下限装 3.0/3.1 会在 import `gsuid_core.ai_core.mcp.server` 时崩。
- **⬆️ 依赖** `sqlmodel` 补下限 `>=0.0.14`：0.0.14 起才支持 pydantic v2，更早的版本只认 pydantic v1。
- **⬆️ 依赖** `pillow` 下限 `10.2.0` 提到 `12.0.0`：12 起 `Image.getdata()` 弃用（14 移除），三处取像素改用 `tobytes()` 按字节读；实测 L / RGB / RGBA 下新旧写法逐值相同，人脸指纹的 dHash 一致。
- **📌 依赖** `uv.lock` / `poetry.lock` / `pdm.lock` 按同一套约束全量重解并互相对齐：113 个包升到该约束下的最新版（含 `pydantic` 2.12.5 → 2.13.5），其中 20 个是主版本跳（`cryptography` 50、`pillow` 12、`rich` 15、`urllib3` 2.8、`protobuf` 7 等）。
- **📌 依赖** 升版至 `0.11.1`，`gsuid_core/version.py` 从 `0.10.7` 一并对齐：它此前只在升版提交里顺带更新，停在旧值会让状态图与 `core更新记录` 把「当前版本」认在 `0.10.7`。
- **🎨 调整** Core 给插件补依赖时改读 `UV_DEFAULT_INDEX`：PATH 里有 `uv` 就执行 `uv pip install --default-index`，没有就执行 `python -m pip install --index-url`。该变量未设置或为空白时使用 `https://pypi.org/simple`。安装失败即停止，不再依次尝试阿里云、火山引擎、清华和官方 PyPI。
