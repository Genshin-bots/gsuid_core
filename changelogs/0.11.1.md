# 0.11.1 — token 用量恢复记账，`pydantic-ai-slim` 升到 2.54

发布于 2026-10-08 · 提交范围见 `pyproject.toml` 的 `version` 变动 · [返回索引](CHANGELOG.md)

`genai-prices` 0.1.x 的用量字段与 `pydantic-ai` 2.13 不兼容，token 统计会静默归零；这一版升到上游修好的组合：`pydantic-ai-slim` 2.54.0 + `genai-prices` 0.1.9。

- **🐛 修复** `genai-prices` 0.1.x 的 `Usage` 会多带出 `pydantic-ai` 2.13 不认的键（如 `output_reasoning_tokens`），让用量提取静默失败、每次模型调用都记成 0——网页控制台日历、预算账本与 TPS 同步归零。
- **⬆️ 依赖** `pydantic-ai-slim` 从 `>=2.13.0` 提到 `>=2.54.0`：它是第一个把 `output_reasoning_tokens` 收进 `RequestUsage` 的版本（2.53.0 及以前都没有）；锁文件随之把 `openai` 升到 3.26、`httpx2` 升到 2.13.1，`pydantic` 保持 2.12.5。
- **🎨 调整** 模型工厂按 SDK 的 HTTP 库分池：`openai` 3.x 与 `anthropic` 1.x 的 `http_client` 形参只收 `httpx2.AsyncClient`，这两家改传 `httpx2` 池并保留同款 §23 墙钟（connect 15s / read 180s / write 60s / pool 30s），`gemini` 仍走 `httpx` 池；`httpx2>=2.12.0` 同时列为直接依赖。
- **⬆️ 依赖** `genai-prices` 的 `<0.1` 上限移除，改为 `>=0.1.9`。
- **⬆️ 依赖** `pydantic-ai-skills` 约束到 `<1`：2.x 搭配 harness ≥0.52 会构造只支持 POSIX 的工作区后端，Windows 上构造技能能力即抛 `NotImplementedError`（实测 2.1.0 + harness 0.54.0），等上游支持非 POSIX 再迁。
- **⬆️ 依赖** `pytakumi` 最低版本提到 `0.1.5`。
- **📌 依赖** 升版至 `0.11.1`，`gsuid_core/version.py` 从 `0.10.7` 一并对齐：它此前只在升版提交里顺带更新，停在旧值会让状态图与 `core更新记录` 把「当前版本」认在 `0.10.7`。
