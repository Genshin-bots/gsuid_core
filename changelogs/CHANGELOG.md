# GsCore 更新日志

每个版本一个文件，共 36 个已发布版本，累计 963 个提交，覆盖 2023-06-18 至 2026-10-08。

## 怎么用这份记录

- **改代码前** 先看相关版本的记录，确认改动是否与既有设计冲突。
- **改代码后** 判断这次改动是否够格进更新日志：新能力、行为变化、破坏性变更要记；修错字、改文案、内部重构不用记。判断标准见 `AGENTS.md` 的「变更记录」一节。
- **写法** 参照 [human-talk 技能](../.agents/skills/human-talk/SKILL.md)：一句话一件事、写清执行者、不用「优化 / 完善 / 若干」这类空词，数字要带条件。
- **证据** 每条都挂 commit 链接，链接要能打开。改完可以先写条目、链接后补；下次动这份记录时，把没链接的条目逐条查一遍，已提交的补上短号。

## 约定

- **版本边界** 取自 `pyproject.toml` 里 `version` 字段的每一次改动，不是 Git tag。仓库只有一个 tag（`webconsole-v0.0.1`），不作为版本依据。
- **提交归属** 升版打开这一版。某一版的提交 = 该版升版之后、到下一版升版之前的全部提交；升版当天的发布说明也留在该文件。不要为同一版本号另开 `-unreleased`。`0.11.0` 之前各版仍按当时「升版关闭周期」书写，不再改写。
- **覆盖** 全部 956 个提交都能追溯到某一版。信息过少的提交（仅 `update`、纯合并、升版本身）合并成一条并保留链接，不单独成条。
- **emoji** 沿用仓库自己的 commit emoji 约定：`✨` 新增、`🐛` 修复、`🎨` 调整、`⚡` 性能、`💥` 破坏性变更、`🔒` 安全、`⬆️` 依赖、`♻` 重构、`🔧` 工具、`📦` 打包、`🍱` 配置、`📝` 文档、`🚨` CI、`🧪` 评测、`👽` 未完工、`🌐` i18n、`💻` 前端、`💚` 修补、`🔖` 升版、`✏️` 笔误、`🚀` 上线、`📌` 锁版本、`⚗️` 数据库、`🔌` MCP、`🔥` 紧急或移除。
